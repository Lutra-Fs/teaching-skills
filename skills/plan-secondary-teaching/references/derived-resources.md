# Derived resources: one source, several matching materials

Read when the teacher wants material made from something that already exists: a practice sheet, workbook or revision paper, versions of one task, a quiz, or a follow-up on quiz results. The **source** is the lesson, deck, reading or unit already taught or approved; every derived piece answers to it.

## 1. Fix the source and the set

1. Read the source and its program row. List what was taught (terms, cases, representations, methods) and what was only mentioned. Questions draw on the taught list; anything beyond it is flagged to the teacher as new content.
2. Agree the set before making it: which pieces, for which students, how many minutes each. Make the pieces asked for and offer the others by name.
3. Keep a **source map** in the teacher version: each question beside the slide, page or section it rests on.
4. Hold terms, cases, diagrams, notation and names identical across every piece and identical to the source.

## 2. Practice sheet, workbook or revision paper

- Order the sections by the learning goal. A common order is recall, then applying to a given stimulus, then a combined case; use the sections this goal needs.
- Each question shows its marks and has answer space sized to the expected response: lines for prose, a grid for a table, room for working.
- A stimulus (diagram, code, email, data table) sits on the same page as its questions and holds every detail the marking relies on.
- Deliver two files. The student version has the questions. The teacher version adds worked answers, the point each mark is given for, accepted alternatives, banded descriptors for extended responses, and the source map.
- For print layout, fill the school's template when one exists; otherwise hand the finished content to a document skill such as `kami`, with this default:
  - Name and date lines at the top; lettered sections with a heading each.
  - The key term of each question in bold; the marks in brackets at the end of the question.
  - Ruled answer lines, about two per mark and more for an extended response; a ruled table where the answer is a comparison or a matrix.
  - A scenario or case in a boxed panel directly above its questions.
  - Answers start on a new page: "1 mark for …" point by point, and a levels scheme (marks band, then what a response in that band does) for an extended response.

## 3. Versions of one task

Versions share one learning intention, one stimulus and one look. Change one dimension at a time, and name it in the teacher version.

| Dimension | What changes | What stays |
|---|---|---|
| Language load | Sentence length, a glossary, a word bank | The reasoning the question asks for |
| Support | A worked step, partial completion, a trace table, a sentence starter | The decision students make themselves |
| Complexity | How many conditions interact; a familiar case or a transfer case | The concept |
| Response mode | Written, annotated diagram, oral, table | The criterion being judged |

- Choose versions from current class evidence and the barrier it shows (`scaffolding-differentiation.md`, Procedure). Label them by a task feature or a neutral mark, and assign them lesson by lesson.
- An extension goes deeper: a transfer case, a justification, a trade-off.
- After editing a question in one version, carry the edit to the other versions, the answers, the source map and any slide that refers to it, and list what you updated.

## 4. Quiz from taught content

- Write items from the taught list. Pick each type for its job: multiple choice to diagnose a misconception, matching for term and function, ordering for a process, short answer for an explanation. Item rules are in `workflow-lesson.md` section 2.
- For each item the teacher version records what it checks, the misconception each wrong option shows, and the teacher's next move.
- For a quiz platform, fill the platform's own import template (the teacher profile names the file), then re-read the filled file: one correct answer flagged per item, text within the platform's length limits, a time limit set.

## 5. From results to the next lesson

Record one line per item or goal in the lesson folder:

`item or goal | response spread | commonest wrong answer | support students had | likely reasons | quick check | change to the next lesson`

Give at least two likely reasons where two are plausible: a wrong ordering answer may show a missing idea about dependency, a misread instruction, or trouble with the platform. The quick check is two or three students explaining their answer; the change names the step to reteach and how.

## 6. Check before delivery

Apply each check to every question.

1. **Answerable:** every figure, field, code line or value the question refers to is on the page and is enough to answer it. An empty placeholder (a sender address, a file name) is the commonest defect in generated workbooks.
2. **Answers come from the question:** each mark can be earned from the stimulus and what was taught. The stimulus licenses the inference the answer makes: devices drawn on one switch do not show a shared subnet.
3. **Marks are executable:** each mark has a stated point or band condition, the parts add up to the total, and a second marker would reach the same score.
4. **Claims are proportionate:** an answer states its conditions ("with no other control in place") where an absolute would be false.
5. **The setting is familiar:** names, places, currency, laws and examples are local and known to the class, unless the unfamiliar detail is the thing being assessed. The course named in the title is the course this class studies.
6. **It prints:** each stimulus sits with its questions, a question keeps its answer lines on the same page, tables stay whole across pages, and the student and teacher versions are separate files.

**Done when** all six hold for every question, or each failing question is listed with its reason.
