# Workflow: unit, course pacing and recovery

Use for creating, adapting or auditing a unit or module sequence, and for course or semester readiness, coverage, pacing and lost-time recovery. Read `continuity-progression.md` and the course card; `frameworks-quality.md` for a new unit design; `assessment-reporting.md` when the unit carries formal assessment.

## Unit sequence

1. **Inherit before designing.** Read the course allocation, program version, common outcomes and content, assessment dates and handoffs, and the existing unit and resources. Identify which layer the teacher owns; changes to a common faculty sequence need its owner's approval.
2. **Change or design.** For an approved unit, locate the requested change and keep the common sequence, conventions, evidence and artefacts. For a new unit, use backward design: desired results (every content point of the unit with its learning components, per `curriculum-lock.md`), then acceptable evidence and criteria, then the learning sequence.
3. **Spread the learning across lessons.** Plan modelling, attempts, feedback, retrieval and growing independence over the sequence instead of forcing every phase into every lesson. Each lesson is one real period (see `workflow-lesson.md` §1 step 3).
4. **Estimate time honestly,** including repeated practice and practical or project operations, from class and faculty evidence before model guesses. If the allocation threatens course commitments, run the pacing steps below and return a resolved allocation or a labelled proposal.
5. **Map each boundary:** the evidence a lesson needs coming in, the stable terms and representations, the output it must hand on, and a recovery route.
6. **Produce only the requested depth** using `assets/unit-program-pack.md`. Detail only the next lesson through `workflow-lesson.md`; later lessons stay one row each and are revised after each taught lesson. A unit request alone does not need a semester of slides.
7. **Review the sequence and any anchor tasks** with the material review in `frameworks-quality.md`. **Done when** every required content point is allocated to a lesson or listed as a shortfall with an owner.

## Course pacing and recovery

1. Read the adopted sequence, calendar, common assessment and project dates, and actual progress. Inspect only the horizon asked about.
2. Keep one coverage view: required content not yet taught, taught content needing recovery, usable lessons remaining, protected assessment, practice and revision, real resource and safety dependencies, and a buffer. Content presented is not content learned.
3. If on track, say so and return the allocation. If off track, identify the blocking gaps, compare recovery options, remove only non-essential overhead, and recalculate.
4. Show the consequence of each adjustment: time recovered or needed, what moves, and which deadline or shared dependency it affects. Stage 6 deadlines are fixed; Stage 4 and 5 deadlines have limited room too.
5. Apply authorised edits; present changes outside the teacher's authority as proposals for the mentor or faculty. If the plan cannot fit, show the shortfall with honest estimates and every content point accounted for.

## Deliver

The updated sequence or coverage view, the risks and recovery options with owners, and the unresolved dependencies. Farther lessons may stay coarse; every required content point has a place.
